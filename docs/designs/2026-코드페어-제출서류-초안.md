### 작품 요약 (12pt, A4 1장 이내)

**작품 주제**

일반 공간 음향 헤드폰(AirPods Pro, Sony WH-1000XM 등)만으로 후천성 시각장애인이
스포츠 경기를 실시간으로 '느낄' 수 있는 웹 기반 공간 음향 관람 시스템.

**작품의 설명 (제안하는 해법 및 근거)**

성인이 된 이후 시력을 잃은 사람들(후천성 시각장애인)은 시각을 잃기 전부터 스포츠 팬이었던 경우가 많다.
그러나 현재 제공되는 음성 해설은 "왼쪽으로 패스합니다"와 같이 공간적 맥락을 전달하지 못한다.
공간 감각이 없으면 경기의 긴장감과 몰입감을 느낄 수 없다.

SonicField는 두 가지 기술을 결합하여 이 문제를 해결한다:

1. **이어콘(Earcon)**: 경기 이벤트(골, 파울, 태클, 코너킥, 페널티)를 각각 고유한 음향 아이콘으로 표현한다.
   골 = 종소리, 파울 = 호루라기, 태클 = 충격음, 코너킥 = 핑 소리, 페널티 = 긴장 효과음.
2. **HRTF 공간 음향**: 웹 브라우저 내장 Web Audio API의 PannerNode(HRTF 모드)를 사용하여
   볼 위치를 3D 공간에서 소리로 표현한다. 왼쪽에서 일어난 태클 소리는 왼쪽 귀에서, 오른쪽 골은
   오른쪽에서 들린다. 경기장을 5×3 구역 격자(가로 5열 = 좌우, 세로 3행 = 앞뒤)로 분할하고,
   각 이벤트의 발생 위치에 맞게 음향을 패닝한다.

데이터 파이프라인: K리그 이벤트 API(골, 파울 등 저비용 이벤트) + 서버 사이드 CV(YOLO 기반 볼
위치 추적)의 하이브리드 방식. 브라우저 기반 웹앱으로 별도 앱 설치 없이 사용 가능.

**기존 작품(해법)과의 차이점**

| 솔루션 | 공간 음향 | 특수 하드웨어 불필요 | 집에서 사용 | 실시간 |
|--------|-----------|---------------------|------------|--------|
| 음성 해설 | ✗ | ✓ | ✓ | ✓ |
| Touch2See (Orange/5G) | ✓ | ✗ (전용 기기) | ✗ (경기장 전용) | ✓ |
| Field of Vision (더블린) | ✓ | ✗ (햅틱 기기) | △ | ✓ |
| **SonicField** | **✓** | **✓** | **✓** | **목표** |

기존 솔루션들은 모두 '더 나은 라디오(더 많은 설명)'를 만들거나 특수 하드웨어가 필요하다.
SonicField는 설명 없이 공간 음향 자체가 경험이 되는 '시각장애인을 위한 TV'를 목표로 한다.

**결과**

현재 계획 수립 단계. Gate 0(API/권리 조사) → Gate 1(사용자 발굴 인터뷰 3명) →
Gate 2(공간 음향 인코딩 검증 프로토타입 테스트) 순으로 검증 후 개발 진행 예정.

### Ⅰ 주제

#### 1. 개발 배경 및 필요성

대한민국 등록 시각장애인은 약 25만 명이며, 이 중 상당수는 성인이 된 이후 질병이나 사고로
시력을 잃은 후천성 시각장애인이다. 후천성 시각장애인은 시력을 잃기 전부터 스포츠 경기를 즐겨
시청하던 팬인 경우가 많아, 경기를 따라가고 싶은 강한 동기를 가지고 있다.

현재 이들이 스포츠를 즐기는 주된 방법은 라디오 또는 TV 음성 해설이다. 그러나 "공이 왼쪽으로
빠르게 이동합니다", "선수가 오른쪽에서 슛을 시도합니다"와 같은 언어 설명은 공간적 맥락을 전달하는
데 근본적인 한계가 있다. 시력이 있을 때 TV 화면을 통해 느꼈던 '공이 날아오는 방향', '선수 간의
거리감', '골 순간의 공간적 긴장감'은 언어만으로는 재현이 불가능하다.

Touch2See(프랑스 Orange·5G 협력)나 Field of Vision(아일랜드) 같은 해외 선행 연구들이 공간
음향+햅틱 피드백을 시도했으나, 모두 경기장 현장 방문과 전용 하드웨어가 필요하다. 집에서, 일반
헤드폰만으로 사용할 수 있는 솔루션은 존재하지 않는다.

따라서 본 작품은 다음 문제를 해결하고자 한다:
> **후천성 시각장애인이 별도 하드웨어 없이, 집에서, 실시간으로 스포츠 경기의 공간적 맥락을
> 느낄 수 있는가?**

#### 2. 개발 주제(목적)

Web Audio API의 HRTF(Head-Related Transfer Function) 기반 공간 음향 기술과 이어콘
(Earcon — 사전 정의된 음향 아이콘) 문법을 결합하여, 후천성 시각장애인이 일반 공간 음향
헤드폰만으로 K리그 축구 경기의 실시간 공간적 맥락을 '들어서 느낄' 수 있는 웹 앱을 개발한다.

핵심 목표:
- 골, 파울, 태클, 코너킥, 페널티 5가지 이벤트를 이어콘으로 표현
- 각 이어콘의 발생 위치(경기장 좌/우/중앙, 근거리/원거리)를 HRTF 공간 음향으로 표현
- 특수 하드웨어 없이 AirPods Pro, Sony WH-1000XM 등 일반 공간 음향 헤드폰으로 동작
- 스크린 리더(VoiceOver, NVDA) 완전 호환, 키보드 네비게이션 지원

#### 3. 유사 제품(연구) 및 차별점

**유사 제품 조사**

| 솔루션 | 핵심 방식 | 하드웨어 | 접근성 | 한계 |
|--------|----------|---------|--------|------|
| Touch2See | 5G 햅틱 + 공간 음향 | 전용 조끼+기기 필요 | 경기장 전용 | 현장 방문 필수, 비용 높음 |
| Field of Vision | 햅틱 + 공간 음향 | 햅틱 밴드 필요 | 일부 원격 가능 | 전용 기기 구매 필요 |
| OneCourt (NBA) | 햅틱 + AI 해설 | 전용 기기 | 경기장 전용 | 현장 방문 필수 |
| 일반 음성 해설 | 언어 설명 | 없음 | 어디서나 | 공간 정보 없음 |
| **SonicField** | **이어콘 + HRTF** | **없음(일반 헤드폰)** | **집에서** | 개발 중 |

**차별점**

1. **하드웨어 장벽 없음**: 기존 경쟁 솔루션은 모두 전용 기기(햅틱 밴드, 조끼 등)가 필요하거나
   경기장 현장 방문이 필수다. SonicField는 이미 광범위하게 보급된 AirPods Pro, Sony
   WH-1000XM 같은 일반 소비자 공간 음향 헤드폰으로 동작한다.
2. **설명이 아닌 감각**: 기존 솔루션들은 모두 '더 많은 정보 제공(더 나은 라디오)'이라는
   방향으로 설계되었다. SonicField는 이어콘 자체가 경험이 되어, 말하지 않아도 위치가 느껴지는
   '시각장애인을 위한 TV'를 지향한다.
3. **접근성 우선 설계**: 브라우저 기반 웹앱으로 앱 설치 불필요. 전체 인터페이스 ARIA 라벨링,
   키보드 네비게이션, 스크린 리더 완전 호환.

### Ⅱ 작품 설계 및 제작

#### 1. 작품 설계

**설계 개념**

경기장을 5×3 구역 격자로 추상화한다:
- 5열 (가로): 열 1 = 완전 왼쪽, 열 3 = 중앙, 열 5 = 완전 오른쪽
- 3행 (세로): 행 1 = 근거리(내 팀 골대 방향), 행 3 = 원거리(상대 팀 골대 방향)
- 이벤트 발생 구역에 따라 Pan(좌우) 및 Depth(앞뒤) 값이 자동 계산됨

설계 시 핵심 원칙:
- 이어콘은 200~800ms, 48kHz 스테레오 WAV, 1MB 미만으로 제한 (지연 없는 사전 로딩)
- 선수 교체는 공간 위치 없이 스테레오 중앙 알림음으로만 처리 (위치 정보 불필요)
- Firefox에서 HRTF 품질이 Chrome/Safari 대비 열위 — 앱 시작 시 브라우저 권장 안내 표시

**작동 원리**

```
[K리그 이벤트 API] ──────────────────────────────────────────┐
                                                              ▼
[방송 스트림] → [서버: YOLO 볼 추적 (CV)] → [내부 이벤트 스키마] → [SSE 전송]
  x: 0-100, y: 0-100, event_type, timestamp, team               │
                                                              ▼
                                              [브라우저: Web Audio API]
                                              PannerNode (HRTF 모드)
                                              - azimuth 계산 (x → 좌우 pan)
                                              - distance 계산 (y → 앞뒤 depth)
                                              - 이어콘 AudioBuffer 재생
                                                              │
                                                              ▼
                                              [사용자: 공간 음향 헤드폰]
```

내부 이벤트 스키마 (JSON):
```json
{
  "event_id": "string",
  "type": "goal | foul | tackle | corner | penalty | substitution",
  "timestamp": "ISO8601",
  "x": 0.0,
  "y": 0.0,
  "team": "home | away",
  "match_id": "string"
}
```

SSE(Server-Sent Events) 방식 선택 이유: 서버→브라우저 단방향 이벤트 푸시에 최적화.
브라우저 내장 EventSource API로 자동 재연결, WebSocket 대비 구현 단순.

**작품 설계 — 5개 화면**

| 화면 | 이름 | 기능 |
|------|------|------|
| 1 | 경기 선택 | 라이브 경기 목록 (K리그 우선; API 없을 시 프리미어리그 대체); "청취 시작" 버튼 |
| 2 | 활성 청취 | 5×3 구역 격자 + 볼 위치 표시 점; 이어콘 종류별 음소거 토글; 중지 버튼 |
| 3 | 이어콘 온보딩 | 5개 이어콘 순차 안내; 각 이어콘 이름+설명+샘플 재생 버튼; 건너뛰기 가능 |
| 4 | 이어콘 놀이터 | 5×3 격자 탭 → 선택된 이어콘이 해당 위치에서 재생; 하단 이어콘 선택기 |
| 5 | 설정 | 언어 전환 (KO/EN); 온보딩 초기화; 정보 |

오류 처리:
- K리그 API 다운 → 캐시된 경기 목록 + "연결 끊김" 표시
- CV 추적 소실 → 이어콘 계속 재생, 볼 점 마지막 위치 고정, 배너 표시
- API + CV 모두 소실 → "해설 음성 전환" 옵션 제공
- 음향 기기 미감지 → 청취 시작 전 헤드폰 확인 안내

#### 2. 제작 일정

| 단계 | 내용 | 기간 |
|------|------|------|
| Gate 0 | K리그 API 조사, 방송 권리 법적 검토, CV 컴퓨팅 비용 추정 | 1~3일차 |
| Gate 1 | 후천성 시각장애인 3명 인터뷰 (수요 검증) | 1~7일차 |
| Gate 2 | StatsBomb 데이터 + Web Audio API 프로토타입 제작 및 사용자 테스트 | 8~14일차 |
| 이어콘 설계 | 이어콘 후보 3종 × 5유형 설계 및 Gate 2에서 검증 | Gate 2 병행 |
| 코어 개발 | 이벤트 파이프라인 (SSE), 오디오 엔진, 5개 화면 구현 | Gate 2 통과 후 |
| 군중 음향 | 방송 스트림 군중 음향 에너지 감지 + 방향성 패닝 구현 | 코어 개발 후 |
| 이어콘 놀이터 | 4번 화면 (공간 음향 학습 도구) 구현 | 코어 개발 병행 |
| QA | VoiceOver (iOS/macOS) + NVDA (Windows) 스크린 리더 전체 화면 테스트 | 출시 전 |

### Ⅲ 작품 테스트 계획

#### 1. 테스트 목적

두 단계의 검증 게이트를 통해 개발 전 수요와 기술적 실현 가능성을 검증한다:

- **Gate 1 (수요 검증)**: 실제 후천성 시각장애인 스포츠 팬이 존재하며, 현재 음성 해설에 불만을
  가지고, 공간 음향 대안을 사용할 의사가 있는지 확인한다.
- **Gate 2 (기술 검증)**: 이어콘 + HRTF 공간 음향 방식이 실제로 볼 위치 정보를 전달할 수 있는지,
  그리고 연속 이벤트 상황(실제 경기 속도)에서도 방향 인지가 유지되는지 검증한다.

#### 2. 테스트 방법

**Gate 1 — 후천성 시각장애인 인터뷰**

- 진행 주체: 참가자 (학생 연구자)
- 대상: 후천성 시각장애인 스포츠 팬 3명 (한국 우선; 국제 허용)
- 모집 방법: 한국시각장애인연합회, 장애인 스포츠 단체, Reddit r/Blind, SNS 시각장애인 커뮤니티
- 방법: 1:1 반구조화 인터뷰, 20~30분, 대면 또는 비대면
- 수집 데이터: 이름, 팬인 스포츠 종목, 현재 경기 시청 방법, 구체적인 불편함
- 합격 기준: 3명 중 2명 이상이 다음 3가지 확인:
  (a) 음성 해설만으로는 공간적 맥락 파악 불충분
  (b) 공간 음향 대안을 사용해 볼 의향 있음
  (c) 공간 음향 헤드폰 보유 또는 구매 의향 있음

**Gate 2 — 공간 음향 인코딩 검증 테스트**

- 진행 주체: 참가자 (학생 연구자)
- 대상: 헤드폰 착용 참가자 3명 (후천성 시각장애인 우선; 일반인 가능)
- 도구: StatsBomb 오픈 데이터셋 + Web Audio API PannerNode (HRTF) + HTML 단일 페이지 프로토타입
- 세션 구성 (약 40분):
  - 이어콘 학습: 5개 이어콘 순차 청취 (10분)
  - 정적 테스트: 10분 분량 경기 구간 청취 후 마지막 5개 슛의 발생 위치(좌/중/우 3분의 1) 구술 응답
  - 스트레스 조건 테스트: 3개 이벤트를 실제 경기 속도로 연속 재생 후 마지막 이벤트 위치 구술
  - 브라우저 비교: Chrome 및 Firefox에서 동일한 5개 이어콘 시퀀스를 들어 음질 차이 평가
- 시각장애인 참가자 대응: 시각적 경기장 도표 포인팅 대신 구술로 응답
  ("왼쪽 골대 근처" / "중앙" / "오른쪽 골대 근처")

#### 3. 예상 결과

- Gate 1: 3명 중 2명 이상이 음성 해설의 공간 정보 부족에 동의하고, 공간 음향 대안 사용 의향 표명
- Gate 2 정적: 3명 중 2명 이상이 5개 슛 중 3개 이상의 위치(좌/중/우)를 정확히 구술
- Gate 2 스트레스: 3명 중 2명 이상이 연속 이벤트 후 마지막 이벤트 위치 정확히 구술
- Gate 2 브라우저: Chrome/Safari에서 HRTF 품질이 Firefox 대비 우수할 것으로 예상

#### 4. 기대효과

- 후천성 시각장애인이 경기를 '설명 없이 느끼는' 새로운 관람 경험 제공
- 기존 특수 하드웨어 기반 솔루션 대비 접근 장벽 대폭 낮춤
- 이미 보급된 공간 음향 헤드폰 활용 → 추가 구매 부담 최소화
- 이어콘 + 공간 음향 문법이 다른 스포츠(야구, 농구 등) 및 장르로 확장 가능한 플랫폼 기반 마련
